This document shows expected output examples for the C++ CAN Telemetry Decoder and Fault Analyzer.


## Why Faults Is 3

The total fault count includes validation faults and decoded telemetry faults.

In this sample log:

```text
1 dropped counter fault
1 unknown CAN ID fault
1 invalid DLC fault
```

Total:

```text
Faults: 3
```

---

## Dropped Counter Fault Example

The dropped counter fault comes from CAN ID `0x100`.

The earlier `0x100` counters are:

```text
1
2
4
```

Expected sequence:

```text
1
2
3
4
```

Because counter `3` is missing, the decoder reports:

```text
FAULT: Dropped frame counter detected for ID 0x100: expected 3, got 4
```

---

## Unknown ID Fault Example

The unknown ID fault comes from this frame:

```csv
999,8,01,02,03,04,05,06,07,08
```

The decoder only recognizes:

```text
0x100
0x101
0x102
0x200
```

So `0x999` produces:

```text
FAULT: Unknown CAN ID
```

---

## Invalid DLC Fault Example

The invalid DLC fault comes from this frame:

```csv
100,4,00,08,10,00,00,00,00,00
```

CAN ID `0x100` is supported, but the DLC is `4`.

The expected DLC is:

```text
8
```

So the decoder reports:

```text
FAULT: Invalid DLC
```

---

## Why Decoder Frames Seen Is 8

`Decoder frames seen` counts frames that passed validation and reached the `TelemetryDecoder`.

The sample log has:

```text
10 total frames
2 rejected validation frames
8 decoded frames
```

The two rejected frames are:

```text
0x999 unknown ID
0x100 invalid DLC
```

So:

```text
Decoder frames seen: 8
```

# Stuck Sensor Test

Input file:

```text
data/stuck_sensor_test.csv
```

This file is used to verify the possible stuck sensor warning.

Expected warning:

```text
WARNING: Possible stuck sensor warning: AIN1 stayed at 2048 for 20 active frames
```

Expected summary behavior:

```text
Warnings: 1
Possible stuck sensors: 1
```

The stuck sensor rule is a warning instead of a hard fault because a real sensor can remain steady during valid operating conditions.
